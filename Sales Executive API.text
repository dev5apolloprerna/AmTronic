# Sales Executive API

This document lists every mobile/API endpoint with its URL, request, and example
response. All URLs below are relative to the application URL.

## Base URL and headers

For local development, the base URL is:

```text
http://127.0.0.1:8000/api
```

Send these headers with every request:

```text
Accept: application/json
Content-Type: application/json
```

Except for login, every endpoint also requires the token returned by login:

```text
Authorization: Bearer <token>
```

The API is available only to active employees whose designation permits API
login. A user can access only quotations created by that same user.

## Endpoint list

| Method | URL | Purpose |
| --- | --- | --- |
| `POST` | `/api/login` | Log in and receive a bearer token. |
| `POST` | `/api/logout` | Invalidate the current bearer token. |
| `PUT` | `/api/change-password` | Change the current user's password. |
| `GET` | `/api/dashboard` | Get quotation counts and recent quotations. |
| `GET` | `/api/quotation-lookups` | Get customers, active products, and states for the quotation form. |
| `GET` | `/api/quotations` | List the current user's quotations. |
| `POST` | `/api/quotations` | Create a quotation. |
| `GET` | `/api/quotations/{quotation}` | Get one quotation. |
| `PUT/PATCH` | `/api/quotations/{quotation}` | Update an editable quotation. |
| `DELETE` | `/api/quotations/{quotation}` | Delete an editable quotation. |
| `POST` | `/api/quotations/{quotation}/items` | Immediately save a new product line. |
| `PUT/PATCH` | `/api/quotations/{quotation}/items/{item}` | Save changes to one product line. |
| `DELETE` | `/api/quotations/{quotation}/items/{item}` | Delete one product line. |
| `POST` | `/api/quotations/{quotation}/mark-sent` | Mark a new quotation as sent. |
| `POST` | `/api/quotations/{quotation}/approve` | Approve a sent quotation. |
| `POST` | `/api/quotations/{quotation}/reject` | Reject a new quotation. |

## Authentication

### Login

```text
POST /api/login
Authorization: not required
```

Request:

```json
{
  "email": "sales@example.com",
  "password": "password"
}
```

Successful response (`200 OK`):

```json
{
  "message": "Login successful.",
  "token": "plain-text-bearer-token",
  "token_type": "Bearer",
  "user": {
    "id": 2,
    "name": "Sales Executive",
    "email": "sales@example.com",
    "designation": "Sales Executive"
  }
}
```

Invalid credentials return `422`; an account without API access returns `403`.

### Logout

```text
POST /api/logout
```

Request body: none.

Successful response (`200 OK`):

```json
{
  "message": "Logged out successfully."
}
```

The token used for this request is no longer valid.

### Change password

```text
PUT /api/change-password
```

Request:

```json
{
  "current_password": "password",
  "password": "new-secret",
  "password_confirmation": "new-secret"
}
```

The new password must contain at least 6 characters, and its confirmation must
match.

Successful response (`200 OK`):

```json
{
  "message": "Password changed successfully."
}
```

## Quotations

### List quotations

```text
GET /api/quotations/list
```

All query parameters are optional:

- `status`: `created`, `sent`, `approved`, `rejected`, or `invoice_sent`.
- `search`: quotation number or customer name, up to 255 characters.
- `per_page`: number of results from 1 to 100; the default is 15.

Request body: none.

Successful response (`200 OK`):

```json
{
  "data": [
    {
      "id": 25,
      "quotation_number": "QUO-2026-0025",
      "quotation_date": "2026-09-21",
      "customer": {
        "id": 7,
        "name": "Example Customer"
      },
      "status": "Quotation Created",
      "status_code": "draft",
      "total_amount": 1180,
      "editable": true
    }
}
```

The endpoint does not paginate. It returns every matching quotation owned by
the authenticated user in newest-first order. Send an empty JSON object (`{}`)
to list all of the user's quotations.

### Create quotation

```text
POST /api/quotations
```

Request:

```json
{
  "customer_id": 7,
  "quotation_date": "2026-09-21",
  "gst_applicable": true,
  "discount_amount": 0,
  "admin_charges": 0,
  "material_handling_charges": 0,
  "shipping_address_different": false,
  "shipping_address": "Main Road",
  "shipping_address_line_2": null,
  "shipping_state": "Gujarat",
  "shipping_city": "Surat",
  "shipping_pincode": "395001",
  "items": [
    {
      "product_id": 3,
      "despatch_to": null,
      "size_mtr": 10,
      "no_of_rolls": 2,
      "price_per_mtr": 500
    }
  ]
}
```

Required fields are `customer_id`, `quotation_date`, the shipping address,
state, city and 6-digit pincode, plus at least one item. For every item,
`product_id`, `size_mtr`, `no_of_rolls`, and `price_per_mtr` are required.
`no_of_rolls` must be a whole number. The discount cannot exceed the items'
subtotal.

Successful response (`201 Created`):

```json
{
  "message": "Quotation created successfully.",
  "data": {
    "id": 25,
    "quotation_number": "QUO-2026-0025",
    "quotation_date": "2026-09-21",
    "customer": {
      "id": 7,
      "name": "Example Customer"
    },
    "status": "Quotation Created",
    "status_code": "draft",
    "total_amount": 1180,
    "editable": true,
    "quotation": {
      "id": 25,
      "quotation_number": "QUO-2026-0025",
      "customer_id": 7,
      "user_id": 2,
      "status": "draft",
      "sub_total": "1000.00",
      "gst_amount": "180.00",
      "total_amount": "1180.00",
      "items": [
        {
          "id": 41,
          "product_id": 3,
          "size_mtr": "10.00",
          "no_of_rolls": "2.00",
          "price_per_mtr": "500.00",
          "amount": "1000.00"
        }
      ]
    }
  }
}
```

The nested `quotation` object also includes its other stored fields, timestamps,
customer, product data, and invoice (when one exists).

### Get one quotation

```text
POST /api/quotations/{quotation}/show
```

Example URL: `GET /api/quotations/25`

Request body: none.

Successful response (`200 OK`): the same `data` object shown in the create
response, without the top-level `message`.

### Update quotation

```text
POST /api/quotations/{quotation}/update
```

Example URL: `POST /api/quotations/25/update`

Request: send the complete quotation payload shown under **Create quotation**.

Successful response (`200 OK`):

```json
{
  "message": "Quotation updated successfully.",
  "data": {
    "id": 25,
    "quotation_number": "QUO-2026-0025",
    "status": "Quotation Created",
    "status_code": "draft",
    "editable": true,
    "quotation": {}
  }
}
```

The actual `data` contains the complete summary and nested quotation described
under **Create quotation**. Sent, approved, or rejected quotations cannot be
updated and return `409 Conflict`.

### Incremental product save (mobile draft)

Use these endpoints when an employee taps **Add New Product**, edits a product,
or deletes a product. Each request is written to the database immediately and
returns the complete refreshed quotation, including recalculated `sub_total`,
GST, round-off, and `total_amount`. The employee does not have to tap the final
quotation submit/save button first. If the app is closed, call
`POST /api/quotations/{quotation}/show` when it reopens to restore all saved
products.

#### Add a product

```text
POST /api/quotations/25/items
```

Request:

```json
{
  "product_id": 3,
  "despatch_to": "Customer warehouse",
  "size_mtr": 10,
  "no_of_rolls": 2,
  "price_per_mtr": 500
}
```

Successful response (`201 Created`):

```json
{
  "message": "Quotation product added successfully.",
  "item_id": 42,
  "data": {
    "id": 25,
    "total_amount": 2360,
    "editable": true,
    "quotation": {
      "sub_total": "2000.00",
      "gst_amount": "360.00",
      "total_amount": "2360.00",
      "items": [
        { "id": 41, "product_id": 3, "amount": "1000.00" },
        { "id": 42, "product_id": 3, "amount": "1000.00" }
      ]
    }
  }
}
```

`item_id` is the ID to use for a later update or delete. Only active products
are accepted. `size_mtr` must be at least `0.01`, `no_of_rolls` must be a whole
number of at least `1`, and `price_per_mtr` cannot be negative.

#### Update/save one product

```text
POST /api/quotations/25/items/42/update
```

Request: send the same five product fields shown in **Add a product**. This
endpoint uses `POST` like every other API endpoint. The successful `200 OK`
response is:

```json
{
  "message": "Quotation product updated successfully.",
  "item_id": 42,
  "data": {
    "id": 25,
    "total_amount": 2950,
    "editable": true,
    "quotation": {
      "sub_total": "2500.00",
      "gst_amount": "450.00",
      "total_amount": "2950.00",
      "items": []
    }
  }
}
```

The real `items` array contains every saved line and its related product; it is
shortened above for readability.

#### Delete one product

```text
POST /api/quotations/25/items/42/delete
```

Request body: none.

Successful response (`200 OK`):

```json
{
  "message": "Quotation product deleted successfully.",
  "data": {
    "id": 25,
    "total_amount": 1180,
    "editable": true,
    "quotation": {
      "sub_total": "1000.00",
      "gst_amount": "180.00",
      "total_amount": "1180.00",
      "items": []
    }
  }
}
```

The complete remaining `items` array is returned. All three incremental
endpoints return `403` for another employee's quotation and `409 Conflict` once
the quotation has been sent, approved, or rejected.

#### Recommended mobile API sequence

1. `POST /api/quotations` once to create the editable quotation and keep its
   returned `data.id` as `quotation_id`.
2. Each time **Add New Product** is tapped, call
   `POST /api/quotations/{quotation_id}/items`; keep the returned `item_id`.
3. To save line changes, call
   `POST /api/quotations/{quotation_id}/items/{item_id}/update`.
4. To remove a line, call
   `POST /api/quotations/{quotation_id}/items/{item_id}/delete`.
5. After every add/update/delete, render amounts from the returned `data`; they
   already contain the server-calculated totals.
6. On app restart, call `POST /api/quotations/{quotation_id}/show` and rebuild
   the screen from `data.quotation.items`.
7. When the quotation is ready, call
   `POST /api/quotations/{quotation_id}/mark-sent`. Product lines become
   read-only after this step.

## Common error responses

Missing, expired, or disabled-account token (`401 Unauthorized`):

```json
{
  "message": "Unauthenticated."
}
```

Trying to access another user's quotation (`403 Forbidden`):

```json
{
  "message": "You do not have permission to access this quotation."
}
```

Validation error (`422 Unprocessable Entity`):

```json
{
  "message": "The shipping pincode field must be 6 digits.",
  "errors": {
    "shipping_pincode": [
      "The shipping pincode field must be 6 digits."
    ]
  }
}
```

Invalid workflow operation (`409 Conflict`):

```json
{
  "message": "Send the quotation before approving it."
}
```

Unknown quotation IDs return `404 Not Found`.
