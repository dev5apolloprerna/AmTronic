# Sales Executive API

This document lists every mobile/API endpoint with its URL, request, and example
response. All URLs below are relative to the application URL.

## Base URL and headers

For local development, the base URL is:

```text
http://127.0.0.1:8000/api
```

Send these headers with every request:

```text
Accept: application/json
Content-Type: application/json
```

Except for login, every endpoint also requires the token returned by login:

```text
Authorization: Bearer <token>
```

The API is available only to active employees whose designation permits API
login. A user can access only quotations created by that same user.

## Endpoint list

| Method | URL | Purpose |
| --- | --- | --- |
| `POST` | `/api/login` | Log in and receive a bearer token. |
| `POST` | `/api/logout` | Invalidate the current bearer token. |
| `POST` | `/api/change-password` | Change the current user's password. |
| `POST` | `/api/dashboard` | Get quotation counts and recent quotations. |
| `POST` | `/api/quotation-lookups` | Get customers, active products, and states for the quotation form. |
| `POST` | `/api/quotations/list` | List the current user's quotations. |

| `POST` | `/api/quotations` | Create a quotation. |
| `POST` | `/api/quotations/create` | Create a quotation (compatibility URL). |
| `POST` | `/api/quotations/{quotation}/show` | Get one quotation. |
| `POST` | `/api/quotations/{quotation}/update` | Update an editable quotation. |
| `POST` | `/api/quotations/{quotation}/delete` | Delete an editable quotation. |

| `POST` | `/api/quotations/{quotation}/items` | Immediately save a new product line. |
| `POST` | `/api/quotations/{quotation}/items/{item}/update` | Save changes to one product line. |
| `POST` | `/api/quotations/{quotation}/items/{item}/delete` | Delete one product line. |

| `POST` | `/api/quotations/{quotation}/mark-sent` | Mark a new quotation as sent. |
| `POST` | `/api/quotations/{quotation}/approve` | Approve a sent quotation. |
| `POST` | `/api/quotations/{quotation}/reject` | Reject a new quotation. |

## Authentication

### Login

```text
POST /api/login
Authorization: not required
```

Request:

```json
{
  "email": "sales@example.com",
  "password": "password"
}
```

Successful response (`200 OK`):

```json
{
  "message": "Login successful.",
  "token": "plain-text-bearer-token",
  "token_type": "Bearer",
  "user": {
    "id": 2,
    "name": "Sales Executive",
    "email": "sales@example.com",
    "designation": "Sales Executive"
  }
}
```

Invalid credentials return `422`; an account without API access returns `403`.

### Logout

```text
POST /api/logout
```

Request body: none.

Successful response (`200 OK`):

```json
{
  "message": "Logged out successfully."
}
```

The token used for this request is no longer valid.


### Change password

```text
PUT /api/change-password
```

Request:

```json
{
  "current_password": "password",
  "password": "new-secret",
  "password_confirmation": "new-secret"
}
```

The new password must contain at least 6 characters, and its confirmation must
match.

Successful response (`200 OK`):

```json
{
  "message": "Password changed successfully."
}
```
## Profile

### View profile

```text
POST /api/profile
```

Returns the authenticated employee's `id`, `name`, `email`, `designation`, and
account `status`.

### Update profile

```text
POST /api/profile/update
```

```json
{
  "name": "Sales Executive",
  "email": "sales@example.com"
}
```

Both fields are required and the email must be unique.

## Forgot password

Request a six-digit OTP (no bearer token required):

```text
POST /api/forgot-password/send-otp
```

```json
{ "email": "sales@example.com" }
```

The API always returns the same success response so account email addresses are
not exposed. Eligible accounts receive an OTP by email that expires in 10
minutes. Submit it with the new password:

```text
POST /api/forgot-password/reset
```

```json
{
  "email": "sales@example.com",
  "otp": "123456",
  "password": "new-secret",
  "password_confirmation": "new-secret"
}
```

An OTP permits at most five failed attempts. A successful reset consumes the OTP
and revokes the user's existing bearer token.

## Quotations

### List quotations

```text
GET /api/quotations/list
```

All query parameters are optional:

- `status`: `created`, `sent`, `approved`, `rejected`, or `invoice_sent`.
- `search`: quotation number or customer name, up to 255 characters.
- `per_page`: number of results from 1 to 100; the default is 15.

Request body: none.

Successful response (`200 OK`):

```json
{
  "data": [
    {
      "id": 25,
      "quotation_number": "QUO-2026-0025",
      "quotation_date": "2026-09-21",
      "customer": {
        "id": 7,
        "name": "Example Customer"
      },
      "status": "Quotation Created",
      "status_code": "draft",
      "total_amount": 1180,
      "editable": true
    }
}
```

The endpoint does not paginate. It returns every matching quotation owned by
the authenticated user in newest-first order. Send an empty JSON object (`{}`)
to list all of the user's quotations.

### Dedicated status lists

The mobile quotation tabs may call `POST /api/quotations/pending`,
`POST /api/quotations/approved`, and `POST /api/quotations/rejected`. Each accepts
an optional `search` value and returns the same summary objects as the main list.
Pending includes both newly created and sent quotations that have not yet been
approved or rejected.

### Products before saving a quotation

Use `POST /api/quotations/items` when no quotation ID exists yet. The first call
creates a temporary row in the normal `quotations` table for the authenticated
employee, adds the product to `quotation_items`, and returns `quotation_id`.
For every further product, call the **same URL** and include that `quotation_id`
in the request body. The same ID can be restored with
`POST /api/quotations/{quotation}/show`, even after the app restarts.

When the user saves the quotation, send that `quotation_id` to
`POST /api/quotations` or `POST /api/quotations/create` with all header fields
and omit `items`. The API completes the same quotation row, assigns its official
quotation number, and keeps its existing products and calculated amounts.

#### Add the first product

```text
POST /api/quotations/items
Authorization: Bearer <token>
```

Request (do not send `quotation_id` on the first call):

```json
{
  "product_id": 3,
  "description": "Clear glass product",
  "qty": 2.5,
  "rate": 80
}
```

Response (`201 Created`):

```json
{
  "message": "Product saved before quotation completion.",
  "quotation_id": 41,
  "item_id": 86,
  "data": {
    "id": 41,
    "quotation_number": null,
    "quotation_date": null,
    "status": "Quotation Created",
    "status_code": "draft",
    "total_amount": 200,
    "editable": true,
    "quotation": {
      "id": 41,
      "user_id": 2,
      "is_temporary": true,
      "items": [
        {
          "id": 86,
          "product_id": 3,
          "product_name": "Clear Glass",
          "description": "Clear glass product",
          "qty": 2.5,
          "rate": 80,
          "amount": 200
        }
      ]
    }
  }
}
```

#### Add another product with the same API

Call the identical URL and send the returned `quotation_id`:

```text
POST /api/quotations/items
```

```json
{
  "quotation_id": 41,
  "product_id": 8,
  "description": "Second product",
  "qty": 1,
  "rate": 100
}
```

The response contains the same `quotation_id` and the complete updated product
list. Save `quotation_id` in the app state; after reopening the app, restore the
temporary quotation with `POST /api/quotations/41/show`.

#### Complete the quotation

```text
POST /api/quotations
```

```json
{
  "quotation_id": 41,
  "customer_id": 7,
  "quotation_date": "2026-09-23",
  "gst_applicable": true,
  "shipping_address_different": false,
  "shipping_address": "Main Road",
  "shipping_state": "Gujarat",
  "shipping_city": "Surat",
  "shipping_pincode": "395001"
}
```

Do not send `items` in this request. A successful `201 Created` response keeps
`data.id` equal to `41`, changes `data.quotation.is_temporary` to `false`, assigns
`quotation_number`, and retains the previously added product lines.


### Create quotation

```text
`POST /api/quotations/create` is an equivalent compatibility URL. Prefer
`POST /api/quotations` for new integrations.
```

Request:

```json
{
  "customer_id": 7,
  "quotation_date": "2026-09-21",
  "gst_applicable": true,
  "discount_amount": 0,
  "admin_charges": 0,
  "material_handling_charges": 0,
  "shipping_address_different": false,
  "shipping_address": "Main Road",
  "shipping_address_line_2": null,
  "shipping_state": "Gujarat",
  "shipping_city": "Surat",
  "shipping_pincode": "395001",
  "items": [
    {
      "product_id": 3,
      "description": "Clear glass roll",
      "qty": 2,
      "rate": 500
    },
    {
      "product_id": 8,
      "description": "Second product line",
      "qty": 3,
      "rate": 100
    }
  ]
}
```

The `items` array accepts multiple products; every object is saved as a separate
quotation line in the same database transaction. Required fields are
`customer_id`, `quotation_date`, the shipping address,

state, city and 6-digit pincode, plus at least one item. For every item,
`product_id`, `size_mtr`, `no_of_rolls`, and `price_per_mtr` are required.
`no_of_rolls` must be a whole number. The discount cannot exceed the items'
subtotal.

Successful response (`201 Created`):

```json
{
  "message": "Quotation created successfully.",
  "data": {
    "id": 25,
    "quotation_number": "QUO-2026-0025",
    "quotation_date": "2026-09-21",
    "customer": {
      "id": 7,
      "name": "Example Customer"
    },
    "status": "Quotation Created",
    "status_code": "draft",
    "total_amount": 1534,
    "editable": true,
    "quotation": {
      "id": 25,
      "quotation_number": "QUO-2026-0025",
      "customer_id": 7,
      "user_id": 2,
      "status": "draft",
      "sub_total": "1300.00",
      "gst_amount": "234.00",
      "total_amount": "1534.00",
      "items": [
        {
          "id": 41,
          "product_id": 3,
          "product_name": "Glass Roll",
          "description": "Clear glass roll",
          "qty": 2,
          "rate": 500,
          "amount": 1000
        },
        {
          "id": 42,
          "product_id": 8,
          "product_name": "Second Roll",
          "description": "Second product line",
          "qty": 3,
          "rate": 100,
          "amount": 300
        }
      ]
    }
  }
}
```

The nested `quotation` object also includes its other stored fields, timestamps,
customer, product data, and invoice (when one exists).

### Incremental product save (mobile draft)

Use these endpoints when an employee taps **Add New Product**, edits a product,
or deletes a product. Each request is written to the database immediately and
returns the complete refreshed quotation, including recalculated `sub_total`,
GST, round-off, and `total_amount`. The employee does not have to tap the final
quotation submit/save button first. If the app is closed, call
`POST /api/quotations/{quotation}/show` when it reopens to restore all saved
products.

#### Add a product

```text
POST /api/quotations/25/items
```

Request:

```json
{
  "product_id": 3,
  "description": "Clear glass roll",
  "qty": 2,
  "rate": 500
}
```

Successful response (`201 Created`):

```json
{
  "message": "Quotation product added successfully.",
  "item_id": 42,
  "data": {
    "id": 25,
    "total_amount": 2360,
    "editable": true,
    "quotation": {
      "sub_total": "2000.00",
      "gst_amount": "360.00",
      "total_amount": "2360.00",
      "items": [
        { "id": 41, "product_id": 3, "product_name": "Glass Roll", "description": "Clear glass roll", "qty": 2, "rate": 500, "amount": 1000 },
        { "id": 42, "product_id": 3, "product_name": "Glass Roll", "description": "Clear glass roll", "qty": 2, "rate": 500, "amount": 1000 }
      ]
    }
  }
}
```

`item_id` is the ID to use for a later update or delete. Only active products
are accepted. `size_mtr` must be at least `0.01`, `no_of_rolls` must be a whole
number of at least `1`, and `price_per_mtr` cannot be negative.

#### Update/save one product

```text
POST /api/quotations/25/items/42/update
```

Request: send the same five product fields shown in **Add a product**. This
endpoint uses `POST` like every other API endpoint. The successful `200 OK`
response is:

```json
{
  "message": "Quotation product updated successfully.",
  "item_id": 42,
  "data": {
    "id": 25,
    "total_amount": 2950,
    "editable": true,
    "quotation": {
      "sub_total": "2500.00",
      "gst_amount": "450.00",
      "total_amount": "2950.00",
      "items": []
    }
  }
}
```

The real `items` array contains every saved line and its related product; it is
shortened above for readability.

#### Delete one product

```text
POST /api/quotations/25/items/42/delete
```

Request body: none.

Successful response (`200 OK`):

```json
{
  "message": "Quotation product deleted successfully.",
  "data": {
    "id": 25,
    "total_amount": 1180,
    "editable": true,
    "quotation": {
      "sub_total": "1000.00",
      "gst_amount": "180.00",
      "total_amount": "1180.00",
      "items": []
    }
  }
}
```

The complete remaining `items` array is returned. All three incremental
endpoints return `403` for another employee's quotation and `409 Conflict` once
the quotation has been sent, approved, or rejected.

#### Recommended mobile API sequence

1. `POST /api/quotations` once to create the editable quotation and keep its
   returned `data.id` as `quotation_id`.
2. Each time **Add New Product** is tapped, call
   `POST /api/quotations/{quotation_id}/items`; keep the returned `item_id`.
3. To save line changes, call
   `POST /api/quotations/{quotation_id}/items/{item_id}/update`.
4. To remove a line, call
   `POST /api/quotations/{quotation_id}/items/{item_id}/delete`.
5. After every add/update/delete, render amounts from the returned `data`; they
   already contain the server-calculated totals.
6. On app restart, call `POST /api/quotations/{quotation_id}/show` and rebuild
   the screen from `data.quotation.items`.
7. When the quotation is ready, call
   `POST /api/quotations/{quotation_id}/mark-sent`. Product lines become
   read-only after this step.

## Common error responses

Missing, expired, or disabled-account token (`401 Unauthorized`):

```json
{
  "message": "Unauthenticated."
}
```

Trying to access another user's quotation (`403 Forbidden`):

```json
{
  "message": "You do not have permission to access this quotation."
}
```

Validation error (`422 Unprocessable Entity`):

```json
{
  "message": "The shipping pincode field must be 6 digits.",
  "errors": {
    "shipping_pincode": [
      "The shipping pincode field must be 6 digits."
    ]
  }
}
```

Invalid workflow operation (`409 Conflict`):

```json
{
  "message": "Send the quotation before approving it."
}
```

Unknown quotation IDs return `404 Not Found`.

## Avoiding the web login page

Always include the `/api` prefix and send `Accept: application/json`. For
example, quotation creation is `POST /api/quotations`, not
`POST /quotations`. The URL without `/api` belongs to the browser application
and can redirect an unauthenticated request to `/login`. A request to the API
URL without a valid bearer token always returns the JSON `401` response shown
above; it does not return or redirect to the HTML login page.
